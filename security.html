Security

Browser and research-library access require explicit trust controls.

Notandia extensions and Zotero plugins execute in privileged environments. The project therefore treats permission scope, configuration validation, message validation, dependency risk, release provenance, update continuity, and incident reporting as product requirements.

Runtime principles

  • Request only permissions required for documented features.
  • Do not load remote executable code.
  • Validate messages, identifiers, URLs, domains, DOI prefixes, profile IDs, actions, colors, and bounded text before use.
  • Keep external requests bounded, time-limited, cancellable, and user-controllable.
  • Render page-derived and profile-derived labels as text instead of writing untrusted data into HTML execution sinks.
  • Preserve released extension identities and persistent settings unless a tested migration exists.

Publisher-profile boundary

Built-in and custom publisher profiles are declarative configuration records. Custom profiles may define a bounded name, domains, DOI prefixes, display action, color, and confidence policy. They cannot define JavaScript, remote resources, executable CSS selectors, or arbitrary DOM operations.

Profile imports are schema-validated, capped, normalized, and stored through browser extension storage. Page styling is idempotent and records original inline properties before applying a selected action so disabling or changing a profile can restore the page state.

Network and integrity controls

  • NCBI and Crossref requests use HTTPS, omit credentials, and use a no-referrer policy.
  • Integrity checks are off by default and Firefox requires separate optional website-content consent.
  • DOI requests are deduplicated, rate-spaced, bounded per scan, and cancelled when disabled or replaced.
  • Crossref relationship direction is validated before a reverse update notice is applied to an original work.

Supply-chain and release controls

  • GitHub Actions are pinned to immutable commit SHAs.
  • Dependency audits, source verifiers, and regression tests run in CI where applicable.
  • Chrome, Edge, Firefox, and Safari packages are generated and verified from one canonical source commit.
  • Checksums and provenance information are generated for supported releases.
  • Release workflows refuse version mismatches, prerelease store publication, and accidental overwrites.
  • Store publication uses separate protected environments and existing released update identities.

Website security

The site is dependency-free static HTML and CSS. It loads no remote JavaScript. Cloudflare response headers enforce a restrictive content security policy, transport security, framing restrictions, MIME sniffing prevention, and a minimal permissions policy.

Reporting vulnerabilities

For sensitive security reports, use GitHub private vulnerability reporting in the affected repository. Include the affected version, platform, impact, reproduction steps, and a minimal proof of concept. Do not publicly disclose exploitable details before maintainers have had a reasonable opportunity to respond.
